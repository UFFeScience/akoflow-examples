# Hybrid kind to GCP: portable local profile

Execute the original producer/consumer file-content checks in two Docker activities on one local host. The local profile verifies actual file handoff and receipt content. It does not measure GCP provisioning, Kubernetes placement, or cross-cloud networking.

The original [cloud placement definition](https://github.com/UFFeScience/akoflow-examples/blob/bf4539082b4c8bcf97197046c251c6174d314e24/real/hybrid-cloud-transfer/kind-cloud-workflow.yaml) remains available as a separate historical version in Hub. It requires the GCP/Kind setup from the documentation. The words `cloud consumed` in the receipt are an inherited fixture label, not evidence that a cloud VM was used.

## Activities and data

1. `produce` writes the original synthetic fixture `akoflow-kind-to-gcp` to `handoff.txt`.
2. AkôFlow materializes this declared dependency into the consumer workspace.
3. `consume` checks the exact bytes and writes `receipt.txt`. Each activity records its successful completion after the content checks pass.

The fixture is generated inline; no external dataset, account or secret is needed for this local profile.

## Local execution

Install Go 1.23+ for the standalone command, or use AkôFlow Desktop/server with Docker. From this directory:

```sh
./prepare.sh && ./run.sh && ./validate.sh
```

For the daemon, import `environment.yaml`, `scope.yaml`, `topology.yaml`, and the digest-pinned YAML returned by Hub. Build a plan and execute it locally. Review the runtime configuration before choosing any original cloud placement variant.
